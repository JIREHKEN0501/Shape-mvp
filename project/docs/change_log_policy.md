# HumanOS Tech — Change & Release Transparency

We believe organizations that trust HumanOS deserve clear visibility into how the platform changes over time.

This document explains how we manage versions and communicate updates.

---

## How We Version HumanOS

HumanOS uses a simple version number like `1.2.0`.

- The first number changes when there is a major update.
- The middle number changes when we add new features.
- The last number changes when we fix bugs or make small improvements.

Example:  
`1.3.2` = Major version 1, feature update 3, patch 2.

---

## What We Track in Our Change-log

For each release we record:

- what was **added** (new tasks, dashboards, features)
- what was **changed** (metrics, routing, scoring behavior)
- what was **fixed** (bugs, edge cases, stability issues)
- any **security / privacy** improvements

We keep this in a CHANGELOG file in our repository so we can always see:

- which version is running
- what changed between versions
- when something was introduced or fixed

---

## Why This Matters for Schools & Organizations

Versioning and change-logging help our partners:

- understand when new features arrive
- know when a behavior or metric changes
- verify that privacy and safety improvements are regularly made
- correlate internal observations with a specific HumanOS release

When a change affects consent, data handling, or minors’ use cases, we flag it internally and ensure our privacy and DPIA documentation stay aligned.

---

If you need a summary of recent changes for an audit, review, or internal governance, we can provide a plain-language release history on request.
