2026-06-11 — Trajectory Dynamics Integration Plan
Objective

Determine how the newly developed Trajectory Dynamics engine should integrate into the HumanOS analytics architecture.

Background

Trajectory Dynamics was originally developed as part of the validation framework to analyze session-level behavioral movement across task attempts.

The engine currently computes:

accuracy_trend
hesitation_trend
trajectory_state
trajectory_shape
accuracy_range

using ordered task-attempt data.

Discovery

Inspection of the production scoring pipeline revealed that task attempts already contain the fields required by the trajectory engine:

{
    "is_correct": ...,
    "hesitation": ...,
    "difficulty": ...,
}

These signals are generated by:

project/app/core/scoring.py

and stored in:

logs/data_log.jsonl

through:

project/app/routes/submit_result.py
Architectural Finding

Inspection of:

project/app/services/analytics.py

revealed an existing temporal analysis module:

_analyze_temporal_behavior(...)

which currently computes:

accuracy_trend
latency_trend
confidence_trend
fatigue_risk

using chronological participant attempts.

This indicates that trajectory reasoning already exists inside the analytics layer.

Current Assessment

Trajectory Dynamics should not be integrated into:

session_summaries.py

at this stage.

Instead, it appears to be a natural extension of:

analytics.py

because both systems operate on ordered behavioral attempts.

Proposed Integration Path

Phase 1:

Keep Trajectory Dynamics independent.

project/app/utils/trajectory_dynamics.py

Phase 2:

Compare outputs between:

_analyze_temporal_behavior()

and

build_trajectory_dynamics()

Identify:

overlapping signals
missing signals
conflicting interpretations

Phase 3:

Determine whether:

_analyze_temporal_behavior()

should:

A. consume Trajectory Dynamics

or

B. be replaced by Trajectory Dynamics

Future Opportunities

Trajectory Dynamics may eventually support:

Recovery Detection
Adaptation Analysis
Difficulty Progression Analysis
Fatigue Detection
Challenge Retention Modeling

using production behavioral data.
